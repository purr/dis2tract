# dis2tract

firefox mv2 extension: content scripts block the feeds; the background blocks porn sites and adult-marked posts, counts the day's time on social media, mirrors the firefox theme and opens the settings from the toolbar button. see README.md for behaviour.

## gotchas

- mv2 on purpose: mozilla keeps mv2 (blog.mozilla.org/addons/2024/03/13), and mv3 host permissions can be revoked or left ungranted, which would silently disable the content scripts on android.
- url rules only (`src/sites.js`), no dom selectors for hiding page parts: they survive redesigns. scroll budget + swipe-chain limit stand in for hiding recommendation rails. the one dom hook is youtube theater mode (`theater()` in sites.js, selectors from improvedtube and control panel for youtube, 2026-10). it writes `wide=1` as a session cookie, as youtube's own toggle does (theater_mode_cookie_max_age_seconds -1, 2026-10); up to 0.7.0 it kept a year-long one, which left videos wide long after theater mode was switched off. storage `wideSet`: true, dis2tract wrote the cookie where there was none; false, taken back, leave it alone; absent, unknown (0.7.0 marked nothing), so it is cleared once. a tweak's `undo(url)` runs from `tweak()` once per url while the tweak or its whole site is off. known limit: after a disable or uninstall the session cookie stays until the session ends.
- feed routes for reddit, facebook, linkedin, threads, bluesky cross-checked against news feed eradicator `src/sitelist/*.ts` (commit 49c9b898c6, 2026-10-28): linkedin's home feed comes as two tabs for some accounts since 2026-09-14, `/feed/` swapping to `/feed/foryou/` after load, the other tab `/feed/network/`; reddit's news feed is `/news` (`?feed=news` until 2026-03, its issue 554).
- youtube's explore pages (gaming, live, music, news, sports, learning) are channels: each answers at `/<name>`, `/feed/<name>_destination`, `/channel/<id>` and `/@<name>` (any case; `/@music` and `/@sports` are 404), and `free()` lets channels through, so `hub()` in sites.js matches all of them. bare paths only exact: `/live/<id>` is one stream. podcasts is no channel. the pages are finite logged out; they are blocked as the site's picks (curl, 2026-10-29).
- instagram: since 2026-08-26 `/reel/CODE/` redirects to `/reels/CODE/`, and the `/reels/` tab jumps to a random `/reels/CODE/`. a single reel and the reels feed share one url form, hence the 3 s "item right after a feed is still the feed" rule in `content.js`. youtube's bare `/shorts` tab behaves the same way.
- the 3 s carry counts from the last tick the url was still a feed (a slow phone swaps late), and back/forward (`popstate`) never carries. `popstate` is judged inside its capture listener, at once: firefox sets the new address before it fires the event (nsDocShell.cpp HandleSameDocumentNavigation, 2026-10), so back onto a feed blocks before the site jumps on; a hash-only popstate is ignored, or it would let a carried item out. chain, carry and the page's used scroll budget (`scroll: { href, screens, more }`) persist per site in storage `trail:<site>` for 60 s, written on a url change, at the scroll cap and on pagehide, so a reload or new tab is not a way out. a link followed from another site starts a new run, judged only on `navigate` loads with `siteFor()`: firefox resends a tab's first referrer on reload and keeps it across pushState (whatwg/html#6813). in private windows the trail lives in background.js memory (`{ trail, value }` / `{ getTrail }` messages) and `recent` is not stored: storage.session is devtools-only for content scripts (schemas/storage.json), and add-on policy keeps private browsing off disk; unlocks, spent, unlockBan, usage and stats stay shared on purpose, so a private window is no way around the limits. a settings write calls `refeed()`, never `onUrl()`, so it keeps the carry and the scroll budget. the 400 ms poll can miss a feed address the site passes through faster (instagram's reels tab jumping to a reel), so background.js forwards every `webNavigation.onHistoryStateUpdated` on the site hosts to the tab: the new address is judged at once (not at the next look, after the site drew the feed), and a reported feed already left again arms the carry (`feedPassed`). that forwarder, its `webNavigation` permission and the trailing-dot fix came in the porn commit (e0ebcc2) and sit next to the porn guard in background.js: taking the porn guard out must keep them, or feed blocking silently loses its fast path.
- tiktok's feed rewrites its url to `/@user/video/ID` while scrolling, so a video url alone does not mean "opened directly".
- reddit serves on `de.`, `en.`, `fr.` ... subdomains: hosts is the manifest wildcard `*.reddit.com`, `hostMatch` picks which subdomains count (`siteFor()`). facebook works the same way: `*.facebook.com`, with hostMatch for www, web, m and the xx-xx language hosts, which serve the whole desktop site themselves and are reached from search results and shared links (curl, 2026-10-29); background.js builds its history-report filter from the manifest matches. tiktok `/shop` 301s to shop.tiktok.com, so it has no rule.
- reddit's player sits in a shadow root: `pauseAll()` walks `openOrClosedShadowRoot` (firefox-only) and adds a play listener per root.
- no `inert` on `<body>`: when the extension is disabled or removed, firefox drops the css but leaves the dom, and an inert body would freeze the tab. a focusin trap keeps focus in the overlay instead, and startup removes a stale `#dis2tract` from an earlier instance. without inert, sites (tiktok, youtube, x) call `focus()` on their players and pulled the cursor out of the answer field mid-word, so the page's `HTMLElement.prototype.focus` is wrapped via `exportFunction` and ignores targets outside the overlay while it is up; the trap returns focus to the last field, not the dialog. `HTMLMediaElement.prototype.play` is wrapped the same way for players in no document (tiktok photo-post music). an exported wrapper dies with the script's sandbox (update, reload, disable) and the page's calls then throw, so `wrap()` stores the page's own method on the wrapper (`dis2tractPage`) and the next instance wraps that, never the dead one; 0.7.0 and older left unmarked wrappers, so a call that throws "can't access dead object" falls back to firefox's own method, read through the xray (the stored mark stays the page's function: an xray function stored there would die at the next update). after a disable or uninstall nothing comes next: play and focus stay broken in open tabs until they reload (known limit). under the unlock sheet the overlay's own children are inert (allowed: they go away with the overlay, unlike `<body>`), and escape closes the sheet. the focusin trap listens on window and stops propagation while blocked: reddit's modal focus trap blurs whatever takes focus on window focusin. the page's `blur()` is not wrapped, which would add another dead-wrapper case.
- the sentence field is a textarea; key events are swallowed while blocked, so enter is caught via `beforeinput` (`insertLineBreak`). an input event that inserts more than one character (`added()`, a common-prefix/suffix diff, so a paste over a selection counts too) is undone: android keyboards insert clipboard text, dictation and swiped words without a paste event. only `typed`, built from those events, is judged: an extension that re-enables paste can swallow the events, and its text is dropped on enter. untrusted input events (a bookmarklet, the console, a userscript typing for the user) are undone too.
- a wrong enter (text or number) stays in the sheet: the challenge's `wrong` verdict, `UNLOCK.penaltySeconds` wait, new challenge. the verdict never names the off word in a text: that made the texts easy. storage `unlockBan` only lengthens the next pause (close/reopen, reload, other sites) and is kept out of the onChanged redraw list: a redraw removes the open sheet, which is how a wrong answer used to drop users back on the block screen with no word why.
- known limit: every time rule trusts the os clock. setting it back stretches an unlock, forward skips cooldowns. there is no trusted clock offline, and it takes deliberate tampering.
- hosts checked with curl (2026-10-27): youtube.com, m.tiktok.com, twitter.com, mobile.x.com, instagram.com, reddit.com, new/m/sh.reddit.com, threads.net all redirect; us.tiktok.com serves the full site itself; facebook sends phones to m.facebook.com, and its language hosts (de-de., es-la., pt-br.) serve the desktop site (2026-10-29).
- "me" urls: youtube `/profile` (yt-dlp issue 147), reddit `/user/me/`, facebook `/me`, linkedin `/in/me/` are login-gated redirects, not verified logged in. tiktok, x, instagram, threads, bluesky have none, hence handle settings.
- theme: content scripts cannot call `browser.theme`, and android has no theme api (bcd `firefox_android: false`). `getCurrent()` returns the light `details` only, never a theme's `dark_theme` variant. reading the theme from storage lands after first paint, so background.js also registers it as css via `contentScripts.register` (injected at document_start). registrations die with the registering page, hence `persistent: true`; the api needs host permissions, hence the host list in `permissions` (a test keeps it equal to the matches, plus the hosts background.js reads). theme values go through a canvas, whose fillStyle keeps its old value for anything that is not a plain color (var() included, which could otherwise load a url on the blocked sites), and out as #rrggbb. a theme's pairs are meant to contrast but nothing checks it (firefox color's default preset is white on light blue, 2.2:1), so a pair is taken only where its 70% muted mix keeps 4.5:1, a translucent field is composited over the page (or the unlock sheet showed the block screen through), and the accent needs 3:1 against page and field. the registered rule is `html #dis2tract:not([data-live])`: firefox takes an injected sheet out of a page only when the page goes, not on unregister() (ExtensionContent.sys.mjs, 2026-10), so it covers the first paint only, and content.js marks the overlay `data-live` once it paints the stored theme.
- block screen layout is static on purpose (a page that shifts under the cursor feels broken): mirror pinned top, block centered, unlock pinned bottom. anything that grows (the unlock flow) opens in a sheet over it, and the question answer has a reserved two-line slot. don't add content that pushes the centered block.
- the mirror shows only app hops ("tiktok 1 min ago, now x. same urge, new app."), never "x was blocked": every feed is blocked, the attempt is the fact. no daily count: page loads and reloads made it wrong. the roast questions (suggestions.js) sting on purpose but tease the habit, not the person; every line <= 38 chars and every link direct, both enforced by tests.
- icon (`icons/icon.svg`): a snapped fishhook (feeds are built to hook you). shapes that read wrong at icon size: two left-aligned bars (the letter f), a cut infinity (an alpha), a slash across the hook (a check mark).
- fade-in and chime only for a block that appears while browsing (`fresh` in `show()`: no overlay before, and `booted`, set after the startup pass: a block that needed storage, a chain or a carry, is a page load). a click on a feed link chimes from the click handler, since its full load draws the block as a first paint. the redraw state is the card's text (feed name, scroll depth), bedtime and the unlock part; when only the unlock part changes, its content is swapped in place, so the search text, focus, question and a running keep-scrolling wait stay. the roast's slot stays empty until storage answers. redraws mark the overlay stale (`dataset.state = ''`) instead of `hide()`, so they never replay either; the first paint of a page load stays instant so no feed flashes. the chime sounds only for a visible tab. a theme change only repaints the open overlay: dynamic themes fire `theme` writes often, and a redraw would close an open unlock sheet each time.
- the chime is `sounds/chime.mp3`, the five nights at freddy's 6 am bell: a copyrighted stock effect (sound ideas, licensed to the game; siivagunner wiki, 2026-10), shipped on purpose: replacing it changes the product, so it is not a cleanup. a muted tab stays quiet (its mute reaches its own media only, never the background page), and android gets no bell: `media.audioFocus.management`, on only there, lets one tab sound at a time, so the bell would stop another tab's audio (settings hide the switch there). the content script sends `'chime'` and background.js plays it: in the page, its moz-extension url would reach the site, and that id is random per browser (mdn), a tracking handle; so no web_accessible_resources. extension pages autoplay by default (`media.autoplay.allow-extension-background-pages`; the default comes from mozilla support-forum posts, not from mozilla's docs).
- reduced motion: keep color/glow fades, stop only movement. a blanket `transition: none` made focus snap wherever the os asks for reduced motion (windows does once its animation effects are off).
- unlock minutes are feed time (`spend()` in content.js): they run only while a visible tab shows a page the unlock lets through and it is in use (`inUse()`): input (pointerdown, wheel, touchmove, keydown, or a scroll under a screen) in the last `UNLOCK.idleSeconds`, or `playingNow()` (page media plus the play-wrapper's set, which reaches shadow roots and detached players). playing alone would make text feeds (x, reddit) free. a muted player counts only within `UNLOCK.mutedSeconds` of input: feeds loop muted clips on their own, and firefox keeps a phone's screen on while a video with a sound track plays, muted or not (`HTMLVideoElement::ShouldCreateVideoWakeLock`), so a phone put down on one counted until its battery died. saved every 5 s and on leaving. the tally lives in storage `spent`, apart from `unlocks`, because every `unlocks` write redraws all block screens and would close an open challenge sheet. only the newest unlock counts, and only until `at + budget + cooldown` (when the next unlock could start): until midnight left a morning unlock opening the feed all day, which looked like a broken block; `doneAt` marks when it ran out, and the cooldown counts from there (or from start + budget if it never ran out); after the extra minute, from `extendedAt` + 1 min, and `left()` expires at end + cooldown. on pagehide, `save(true)` writes spent from memory with no read first: firefox never resolves an api promise for an inactive (closed or back-forward cached) context (ExtensionCommon.sys.mjs wrapPromise) and drops storage events then, hence a `pageshow` replay through `onStorage()` → `refeed()`, never `onUrl()`. the time left shows in its own element, `#dis2tract-left` (never `overlay`; removed at startup like a stale overlay; fixed colors, not the theme). the scroll budget counts screens (each step d / innerHeight at that moment), so a taller window no longer lifts a block; it counts while unlocked too, and keep scrolling sets the extra to max(cap, depth), so the next budget starts where the page is.
- time on social media (storage `usage`, `{ at, ms }` for the day of `at`): `track()` in content.js sends `'use'` to background.js on every look while `inUse()` (the rule unlock minutes use too) and no block screen is up. `countUse()` there counts the time between two notes from any tabs when they are under 2 s apart, so two windows side by side count once, and a sleeping machine or a clock set back adds nothing. per-tab chunks of counted time failed both ways: capped by the time since anyone's last report, a short report from a second window cut the other's chunk; and a tab's own tally went negative when the clock was set back. background.js is the one writer, so two tabs never overwrite each other, and saves within 5 s. unlike the dropped daily count of attempts, reloads can't inflate it. past 30 min (`LOTS_MINUTES`, hunt et al. 2018) `instead()` in suggestions.js turns the roast into that time and one "enough to ..." line; a test holds every line, at every minute of a day, to 38 characters.
- porn sites are not content-script sites: background.js (`guard()`) checks every top-level navigation at `onBeforeNavigate` and again at `onCommitted` (a redirect, short link or alias domain, shows its final address only then), and a frame (reddit's redgifs players) at `onCommitted` only: firefox reports a frame's onBeforeNavigate before a blocker (ublock origin, tracking protection) can cancel it, and a cancelled frame shows nothing (WebNavigation.sys.mjs, 2026-10). `toPorn()` sends the tab to `porn/porn.html?host=<host>` (a list hit) or `?mark=<x|reddit|bluesky>` (a platform's own mark), and the page says what set it off. a page caught after it committed has its own history entry, and going back would load it and send the tab here again: desktop replaces the entry (tabs.update `loadReplace`); android's tabs.update schema has no loadReplace and rejects the whole call (mobile/shared/components/extensions/schemas/tabs.json, 2026-10), so there the page gets `&skip` and its "go back" steps over it. `recheck()` puts every frame of every open tab through guard() once the list is loaded and after each update: webNavigation is not startup-blocking, so pages loaded while firefox starts (session restore, a link from another app on android) and tabs open at install sent no event. `untranslated()` decodes google translate's proxy hosts (www-example-com.translate.goog, `_x_tr_hp`, `0-` for xn--; - shared symbols (`DEFAULTS`, `SITES`, `UNLOCK`, `CHALLENGES`, `NEEDS`, `SHAME`, `URGES`, `LISTED`, `MARKED`, `instead`, `cleanLink`, `cleanText`, and `h`, `pick`, `sub`, `answer`, `paint`, `lateNight`, `wrap` in ui.js) are `var`/function declarations: content script files and the extension pages share globals, not modules. so a page needs every file its globals come from: porn.html loads settings.js only because `lateNight()` falls back to `DEFAULTS`' bedtime (the porn page test checks the script list).
- settings store only values that differ from `DEFAULTS`, so a changed default reaches users; bump `DEFAULTS.version` when the saved shape changes (older saves are discarded). `LIMITS` clamps saved numbers on load.
- stats bumps go through one read-modify-write per event: two concurrent `bump()` calls lose a count.
- run tests with `node --test` (default discovery). `node --test test/` treats the folder as a file and fails.
- the version lives only in `manifest.json` (package.json has none on purpose). a push to main whose version has no `v<version>` tag gets signed (unlisted) and released by `.github/workflows/build.yml`, with its `## <version>` section of CHANGELOG.md as notes; the build fails before signing when that section is missing. what stays out of the package: `webExt.ignoreFiles` in package.json, read by every web-ext command. every action in the release job is pinned to a commit (checkout, setup-node, action-gh-release): that job holds the amo keys and a write token, and a release now reaches every install. no dependabot, so bump the pins by hand (`gh api repos/<owner>/<repo>/git/ref/tags/<tag>` gives the commit); its checkout keeps no token on disk (`persist-credentials: false`) because web-ext's npm tree runs there. the check job (read token, no secrets) stays on tags.
- updates: releases are signed unlisted, and amo's update check never offers unlisted versions, so `update_url` points at `releases/latest/download/updates.json`, which the release job writes from manifest.json before signing (in `$RUNNER_TEMP`: web-ext would pack it from the source folder) and uploads with the .xpi; action-gh-release v3 publishes its draft only after all uploads, so `latest` never lacks it. an installed copy only ever checks the update_url its own version shipped with (extensionworkshop.com updating-your-extension, 2026-10), so that address is a contract the release job checks against `$GITHUB_SERVER_URL/$GITHUB_REPOSITORY`. firefox (source at bf754717, 2026-10) follows github's two 302s for the manifest and the .xpi (`extensions.update.requireBuiltInCerts` and `extensions.install.requireBuiltInCerts` are off on release builds), ignores the content type, needs an https `update_link` and a signed .xpi whose version equals the entry's, and reads the minimum version only under `applications`, not `browser_specific_settings` (ublock origin's updates.json uses the other key, and its minimum is ignored). the update manifest has no android entry, so `gecko_android.strict_min_version` must not rise above gecko's. `web-ext lint` needs `--self-hosted`, or the update_url is an error (amo passes the flag itself for unlisted uploads). 0.5.0 to 0.7.0 have no update_url; an update that adds a warned permission waits for the user's ok.
- design checks: a throwaway harness serves the real files over localhost (browser automation refuses `file:` urls), stubbing `browser.*`, and `window.wrappedJSObject = window` plus an `exportFunction` that assigns: content.js wraps page methods at startup and dies without them.
