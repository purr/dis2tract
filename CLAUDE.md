# dis2tract

firefox mv2 extension: content scripts do the work; the background mirrors the firefox theme and opens the settings from the toolbar button. see README.md for behaviour.

## gotchas

- mv2 on purpose: mozilla keeps mv2 (blog.mozilla.org/addons/2024/03/13), and mv3 host permissions can be revoked or left ungranted, which would silently disable the content scripts on android.
- url rules only (`src/sites.js`), no dom selectors for hiding page parts: they survive redesigns. scroll budget + swipe-chain limit stand in for hiding recommendation rails. the one dom hook is youtube theater mode (`theater()` in sites.js, selectors from improvedtube and control panel for youtube, 2026-10).
- feed routes for reddit, facebook, linkedin, threads, bluesky cross-checked against news feed eradicator `src/sitelist/*.ts` (last commit 2026-08-23).
- instagram: since 2026-08-26 `/reel/CODE/` redirects to `/reels/CODE/`, and the `/reels/` tab jumps to a random `/reels/CODE/`. a single reel and the reels feed share one url form, hence the 3 s "item right after a feed is still the feed" rule in `content.js`. youtube's bare `/shorts` tab behaves the same way.
- the 3 s carry counts from the last tick the url was still a feed (a slow phone swaps late), and back/forward (`popstate`) never carries. chain and carry persist per site in storage `trail:<site>` for 60 s, so a reload or new tab is not a way out. a settings write calls `refeed()`, never `onUrl()`, so it keeps the carry and the scroll budget. the 400 ms poll can miss a feed address the site passes through faster (instagram's reels tab jumping to a reel), so background.js forwards every `webNavigation.onHistoryStateUpdated` on the site hosts to the tab: the new address is judged at once (not at the next look, after the site drew the feed), and a reported feed already left again arms the carry (`feedPassed`).
- tiktok's feed rewrites its url to `/@user/video/ID` while scrolling, so a video url alone does not mean "opened directly".
- reddit serves on `de.`, `en.`, `fr.` ... subdomains: hosts is the manifest wildcard `*.reddit.com`, `hostMatch` picks which subdomains count (`siteFor()`). tiktok `/shop` 301s to shop.tiktok.com, so it has no rule.
- reddit's player sits in a shadow root: `pauseAll()` walks `openOrClosedShadowRoot` (firefox-only) and adds a play listener per root.
- no `inert` on `<body>`: when the extension is disabled or removed, firefox drops the css but leaves the dom, and an inert body would freeze the tab. a focusin trap keeps focus in the overlay instead, and startup removes a stale `#dis2tract` from an earlier instance. without inert, sites (tiktok, youtube, x) call `focus()` on their players and pulled the cursor out of the answer field mid-word, so the page's `HTMLElement.prototype.focus` is wrapped via `exportFunction` and ignores targets outside the overlay while it is up; the trap returns focus to the last field, not the dialog. `HTMLMediaElement.prototype.play` is wrapped the same way for players in no document (tiktok photo-post music). an exported wrapper dies with the script's sandbox (update, reload, disable) and the page's calls then throw, so `wrap()` stores the page's own method on the wrapper (`dis2tractPage`) and the next instance wraps that, never the dead one. after a disable or uninstall nothing comes next: play and focus stay broken in open tabs until they reload (known limit).
- the sentence field is a textarea; key events are swallowed while blocked, so enter is caught via `beforeinput` (`insertLineBreak`). an input event that inserts more than one character (`added()`, a common-prefix/suffix diff, so a paste over a selection counts too) is undone: android keyboards insert clipboard text, dictation and swiped words without a paste event. only `typed`, built from those events, is judged: an extension that re-enables paste can swallow the events, and its text is dropped on enter. untrusted input events (a bookmarklet, the console, a userscript typing for the user) are undone too.
- a wrong enter (text or number) stays in the sheet: the challenge's `wrong` verdict, `UNLOCK.penaltySeconds` wait, new challenge. the verdict never names the off word in a text: that made the texts easy. storage `unlockBan` only lengthens the next pause (close/reopen, reload, other sites) and is kept out of the onChanged redraw list: a redraw removes the open sheet, which is how a wrong answer used to drop users back on the block screen with no word why.
- known limit: every time rule trusts the os clock. setting it back stretches an unlock, forward skips cooldowns. there is no trusted clock offline, and it takes deliberate tampering.
- hosts checked with curl (2026-10-27): youtube.com, m.tiktok.com, twitter.com, mobile.x.com, instagram.com, reddit.com, new/m/sh.reddit.com, threads.net all redirect; us.tiktok.com serves the full site itself; facebook sends phones to m.facebook.com.
- "me" urls: youtube `/profile` (yt-dlp issue 147), reddit `/user/me/`, facebook `/me`, linkedin `/in/me/` are login-gated redirects, not verified logged in. tiktok, x, instagram, threads, bluesky have none, hence handle settings.
- theme: content scripts cannot call `browser.theme`, and android has no theme api (bcd `firefox_android: false`). `getCurrent()` returns the light `details` only, never a theme's `dark_theme` variant. reading the theme from storage lands after first paint, so background.js also registers it as css via `contentScripts.register` (injected at document_start). registrations die with the registering page, hence `persistent: true`; the api needs host permissions, hence the host list in `permissions` (a test keeps it equal to the matches). theme values are checked with `CSS.supports` and `[;{}]` before going into that css.
- block screen layout is static on purpose (a page that shifts under the cursor feels broken): mirror pinned top, block centered, unlock pinned bottom. anything that grows (the unlock flow) opens in a sheet over it, and the question answer has a reserved two-line slot. don't add content that pushes the centered block.
- the mirror shows only app hops ("tiktok 1 min ago, now x. same urge, new app."), never "x was blocked": every feed is blocked, the attempt is the fact. no daily count: page loads and reloads made it wrong. the roast questions (suggestions.js) sting on purpose but tease the habit, not the person; every line <= 38 chars and every link direct, both enforced by tests.
- icon (`icons/icon.svg`): a snapped fishhook (feeds are built to hook you). shapes that read wrong at icon size: two left-aligned bars (the letter f), a cut infinity (an alpha), a slash across the hook (a check mark).
- fade-in and chime only for a block that appears while browsing (`fresh` in `show()`: no overlay before, storage ready). redraws mark the overlay stale (`dataset.state = ''`) instead of `hide()`, so they never replay either; the first paint of a page load stays instant so no feed flashes. the chime sounds only for a visible tab. a theme change only repaints the open overlay: dynamic themes fire `theme` writes often, and a redraw would close an open unlock sheet each time.
- the chime is `sounds/chime.mp3`, the five nights at freddy's 6 am bell: a copyrighted stock effect (sound ideas, licensed to the game; siivagunner wiki, 2026-10), shipped on purpose: replacing it changes the product, so it is not a cleanup. the content script sends `'chime'` and background.js plays it: in the page, its moz-extension url would reach the site, and that id is random per browser (mdn), a tracking handle; so no web_accessible_resources. extension pages autoplay by default (`media.autoplay.allow-extension-background-pages`; the default comes from mozilla support-forum posts, not from mozilla's docs).
- reduced motion: keep color/glow fades, stop only movement. a blanket `transition: none` made focus snap wherever the os asks for reduced motion (windows does once its animation effects are off).
- unlock minutes are feed time (`spend()` in content.js): they run only while a visible tab shows a page the unlock lets through and it is in use: `playingNow()` (page media plus the play-wrapper's set, which reaches shadow roots and detached players) or input (pointerdown, wheel, touchmove, keydown) in the last `UNLOCK.idleSeconds`. playing alone would make text feeds (x, reddit) free. saved every 5 s and on leaving. the tally lives in storage `spent`, apart from `unlocks`, because every `unlocks` write redraws all block screens and would close an open challenge sheet. only the newest unlock counts, and only until `at + budget + cooldown` (when the next unlock could start): until midnight left a morning unlock opening the feed all day, which looked like a broken block; `doneAt` marks when it ran out, and the cooldown counts from there (or from start + budget if it never ran out).
- time on social media (storage `usage`, `{ at, ms }` for the day of `at`): `track()` in content.js counts any page of the sites while `inUse()` (the rule unlock minutes use too) and no block screen is up, and sends `{ used }` chunks of up to 5 s to background.js. `addUsage()` there is the one writer, so two tabs never overwrite each other, and adds no more than the clock moved since the last report, so two windows side by side count once. unlike the dropped daily count of attempts, reloads can't inflate it. past 30 min (`LOTS_MINUTES`, hunt et al. 2018) `instead()` in suggestions.js turns the roast into that time and one "enough to ..." line; a test holds every line, at every minute of a day, to 38 characters.
- porn sites are not content-script sites: background.js (`guard()`) checks every navigation in every frame against oisd's nsfw small list and sends the tab to `porn/porn.html` with `tabs.update`; a frame counts (reddit's redgifs players), and both `onBeforeNavigate` and `onCommitted` are checked, since a redirect (short link, alias domain) shows its final address only at commit. a host with a trailing dot (`tiktok.com.`) matched no rule and no content script, so the tab is sent to the address without it. so the site never shows, the install prompt names no porn hosts, and nothing needs web_accessible_resources. the list is downloaded daily from raw.githubusercontent.com (cors `*`, so no host permission; oisd.nl itself sends no cors header), never kept in the repo: a hand-written list goes stale and publishes which sites were picked; and oisd is gpl-3.0, which bundling would bring into the package. storage `pornList` keeps the last good copy; a download under 1000 domains is refused; the four adult tlds are in code, because a single word from a download could block the whole web. the page plays one of `porn/abah.mp4` and `porn/laugh.mp4` at random, with sound if allowed, else muted with controls. it is built from the block screen's own parts (`src/ui.js`), css (`css/overlay.css`) and theme (`paint()` with the background page's `theme`): it has no stylesheet or colors of its own, so it reads as the same app as the block screen. its words are `SHAME` and `URGES` in suggestions.js, held to the same 38-character, direct-link tests.
- porn inside x, reddit and bluesky: `LABELED` in background.js reads their responses with `webRequest.filterResponseData` (data written on first, untouched) and sends the tab to the porn page when the platform's own adult mark appears: x media `"adult_content":true` (graphic_violence is a separate flag; format from gallery-dl, oldtwitter, twitter-scraper, 2026-10), reddit `nsfw` on a `shreddit-*` element (scrapers disagree whether it sits on `shreddit-post` or `shreddit-content-tags`, so any `shreddit-*` counts) or old reddit's `over18` class, bluesky label `"val"` porn/sexual/nudity (lexicon com.atproto.label.defs). regexes on the raw text, not parsed json: they survive the sites reshuffling their structure. any one mark blocks the page. reading needs `webRequest`, `webRequestBlocking` and host permissions: x and reddit already had them, bluesky's data comes from `*.bsky.network` (logged in, the user's pds) and `public.api.bsky.app` (logged out); a self-hosted pds is not covered. not yet seen against the live sites.
- a feed loaded from scratch is stopped with `window.stop()` right after the first (default-settings) pass covers it. a plain left click on a same-site link to a feed (the youtube logo) is turned into `location.assign()`, a full load that gets stopped the same way: the site's router would otherwise fetch and draw the feed before the block. new-tab and modified clicks load (and stop) by themselves; while unlocked the click goes the usual way. if storage then says it may show (unlocked, feed or site switched off), `reopen()` reloads it with a sessionStorage mark (`dis2tract:pass`) so the reload is let through; without sessionStorage the page is never stopped, since no mark could undo it. a switched-off feed therefore loads twice (known limit).
- `SITES[id].free(url)`: search results and profiles, no scroll budget. x, instagram and facebook profiles are bare first-level paths, so their own first-level pages are excluded by name in the regex; a new first-level page on those sites needs adding there.
- unlock rules live in `UNLOCK` (settings.js) on purpose, with no settings ui: a setting would be the bypass. loosening a setting waits `LOOSEN_DELAY_MINUTES` in storage `pending`; `looser()` decides what counts.
- shared symbols (`DEFAULTS`, `SITES`, `UNLOCK`, `CHALLENGES`, `NEEDS`, `SHAME`, `URGES`, `instead`, and `h`, `pick`, `sub`, `answer`, `paint`, `lateNight` in ui.js) are `var`/function declarations: content script files and the extension pages share globals, not modules. so a page needs every file its globals come from: porn.html loads settings.js only because `lateNight()` reads `UNLOCK.bedtime` (the porn page test checks the script list).
- settings store only values that differ from `DEFAULTS`, so a changed default reaches users; bump `DEFAULTS.version` when the saved shape changes (older saves are discarded). `LIMITS` clamps saved numbers on load.
- stats bumps go through one read-modify-write per event: two concurrent `bump()` calls lose a count.
- run tests with `node --test` (default discovery). `node --test test/` treats the folder as a file and fails.
- the version lives only in `manifest.json` (package.json has none on purpose). a push to main whose version has no `v<version>` tag gets signed (unlisted) and released by `.github/workflows/build.yml`, with its `## <version>` section of CHANGELOG.md as notes; the build fails before signing when that section is missing. what stays out of the package: `webExt.ignoreFiles` in package.json, read by every web-ext command. the release action is pinned to a commit because that job holds the amo keys.
- design checks: a throwaway harness serves the real files over localhost (browser automation refuses `file:` urls), stubbing `browser.*`, and `window.wrappedJSObject = window` plus an `exportFunction` that assigns: content.js wraps page methods at startup and dies without them.
- unverified: tiktok `/friends`; threads `/following`. only run in the fake dom of the tests, never in a real firefox (as of 0.8.0): `window.stop()` at document_start, the feed-link click rewrite, the history-change reports, the porn redirects and adult labels, the chime from the background page, the paste guard against a real right-click extension, the chain in x's phone video viewer (`?currentTweet=`).
- open (review 2026-10-29): the overlay is ordinary page dom, so site scripts can read it after an spa navigation: the mirror (other sites visited, with times), the note during the pause, the handle. a closed shadow root would hide it, but page css does not reach inside one, so overlay.css would have to move into the root. known limits too: a hidden tab (picture-in-picture, background audio) spends no unlock time, bounded by the 23-minute expiry; two windows of one unlocked site can lose a 5 s chunk of spent time to a get/set race. `docs/unlock-sheet.png` still shows the old small "never mind" link.
